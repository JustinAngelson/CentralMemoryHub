# C3 operator scripts (no publish required)

Run only after the tooling PR is reviewed and approved. These scripts do not
modify server code or deployment settings. They have not been run against
production as part of preparing this PR.

Use the workspace venv from the repository root. `-B` prevents bytecode files:

```sh
.local/cmh-v2-venv/bin/python -B v2/c3_mint.py justin
.local/cmh-v2-venv/bin/python -B v2/c3_mint.py claude-routine
.local/cmh-v2-venv/bin/python -B v2/c3_audit.py justin --since 2026-10-15T12:00:00-04:00
.local/cmh-v2-venv/bin/python -B v2/c3_legacy_usage.py
```

Minting prompts privately for the Owner email (the native login requires it)
and password. Nothing is echoed or saved. An existing active non-legacy
credential prevents issuance unless `--rotate` is explicitly supplied. Rotation
mints exactly one credential from the approved standard template, then revokes
the previous active credential(s) and verifies revocation through native HTTPS.
Legacy credentials are never rotated or revoked by these scripts.

The mint command requires a private interactive terminal and refuses redirected
stdout/stdin. It prints the token exactly once, alongside only its principal slug,
credential ID and scopes, framed by a copy/clear warning. Copy directly into the
client header setting; never paste into chat. Run `clear` afterwards and clear
terminal scrollback. Do not use terminal recording, `tee`, output redirection,
debug HTTP logging, or simultaneous mint commands. No automatic retries are made
after an indeterminate HTTP failure; inspect the native credential list first.
Failed rotation attempts revoke the new credential when its ID is known. Partial
old-credential revocations cannot be undone by the operator script.

## Allowed access

- Production origin is `https://centralmemoryhub.com`. TLS validation is enabled,
  redirects are disabled, and environment HTTP proxies are ignored.
- Native HTTPS paths handle Owner login, credential listing, issuance, revocation
  and logout. Scripts never mint directly in SQL or accept scope overrides.
- SQL uses **only** `CMH_PROD_DATABASE_URL`, refuses anything other than
  `cmh_app` on `cmh_v2`, and begins every connection with
  `SET TRANSACTION READ ONLY`. No migrate/v1/development URL fallback exists.
- SQL reads only principal ID/slug/kind/sponsor/status for lookup, and audit
  time/principal/credential ID/operation/outcome metadata for reports. No hashes,
  token material, emails, memory content, versions or trace bodies are selected.
- Audit output is the newest ten matching events, newest first, with only time,
  operation, outcome and credential ID. `--since` requires a timezone.
- Legacy usage counts application audit events, excluding `mcp.transport`
  protocol events, per UTC hour over the exact rolling 24h window. Zero buckets
  are included; first/last buckets can be partial (25 rows per principal).
  Last-seen is the latest audit event across all retained history, including
  transport activity, so a protocol-only connection is not reported as unused.
  Hourly counts are application-audit counts, not raw HTTP/SSE request counts.
