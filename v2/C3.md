# C3 operator scripts (no publish required)

## Creating a namespace

After review/approval, the Owner can create `org.rollups` using:

```sh
.local/cmh-v2-venv/bin/python -B v2/ns_create.py org.rollups --description "Rollup summaries"
```

Client slugs use the same script: substitute `org.clients.example-mechanical`.
Only `org.<seg>` and `org.clients.<seg>` are allowed, with each new segment
matching `[a-z0-9][a-z0-9_-]{0,62}`. `org.finance` and its descendants, private
namespaces, uppercase paths, and additional depth are refused before connecting.
Description is required: 1–200 characters, not blank, with no newlines.
There is no mode override; creation always sends `mode: "flag"`.

The script checks the parent/target using `cmh_app` in READ ONLY transactions,
then prompts privately for an Owner HTTPS session. Creation uses only
`POST /admin/api/namespaces` (`grants.admin`), audited as `namespaces.create`.
After logout it re-reads metadata and requires flag mode and `governed=false`.
An existing target returns its current metadata plus `"status": "already exists"`
without login or mutation, even if it is queue-mode; it is never changed.

Successful stdout is one JSON object: path, mode, governed, namespace ID prefix
(eight characters), and creation timestamp. No description, email, password,
cookies, full IDs, or response bodies are printed. Failures emit a fixed JSON
error to stderr and exit nonzero. A POST is never retried automatically;
inspect native status before any manual rerun after an indeterminate outcome.
The seed entry is for fresh databases only: never run `cmh-seed` against
production, and never use SQL writes to create production namespaces.

## Credential and audit commands

Run only after the tooling PR is reviewed and approved. These scripts do not
modify server code or deployment settings. They have not been run against
production as part of preparing this PR.

Use the workspace venv from the repository root. `-B` prevents bytecode files:

```sh
.local/cmh-v2-venv/bin/python -B v2/c3_mint.py justin
.local/cmh-v2-venv/bin/python -B v2/c3_mint.py claude-routine
.local/cmh-v2-venv/bin/python -B v2/c3_audit.py justin --since 2026-10-15T12:00:00-04:00
.local/cmh-v2-venv/bin/python -B v2/c3_legacy_usage.py
```

Minting prompts privately for the Owner email (the native login requires it)
and password. Nothing is echoed or saved. An existing active non-legacy
credential prevents issuance unless `--rotate` is explicitly supplied. Rotation
mints exactly one credential from the approved standard template, then revokes
the previous active credential(s) and verifies revocation through native HTTPS.
The mint script never rotates or revokes legacy credentials. Legacy retirement
uses the separately approved command below.

The mint command requires a private interactive terminal and refuses redirected
stdout/stdin. It prints the token exactly once, alongside only its principal slug,
credential ID and scopes, framed by a copy/clear warning. Copy directly into the
client header setting; never paste into chat. Run `clear` afterwards and clear
terminal scrollback. Do not use terminal recording, `tee`, output redirection,
debug HTTP logging, or simultaneous mint commands. No automatic retries are made
after an indeterminate HTTP failure; inspect the native credential list first.
Failed rotation attempts revoke the new credential when its ID is known. Partial
old-credential revocations cannot be undone by the operator script.

## Allowed access

- Production origin is `https://centralmemoryhub.com`. TLS validation is enabled,
  redirects are disabled, and environment HTTP proxies are ignored.
- Native HTTPS paths handle Owner login, credential listing, issuance, revocation
  and logout. Scripts never mint directly in SQL or accept scope overrides.
- SQL uses **only** `CMH_PROD_DATABASE_URL`, refuses anything other than
  `cmh_app` on `cmh_v2`, and begins every connection with
  `SET TRANSACTION READ ONLY`. No migrate/v1/development URL fallback exists.
- SQL reads only principal ID/slug/kind/sponsor/status for lookup, and audit
  time/principal/credential ID/operation/outcome metadata for reports. No hashes,
  token material, emails, memory content, versions or trace bodies are selected.
- Audit output is the newest ten matching events, newest first, with only time,
  operation, outcome and credential ID. `--since` requires a timezone.
- Legacy usage counts application audit events, excluding `mcp.transport`
  protocol events, per UTC hour over the exact rolling 24h window. Zero buckets
  are included; first/last buckets can be partial (25 rows per principal).
  Last-seen is the latest audit event across all retained history, including
  transport activity, so a protocol-only connection is not reported as unused.
  Hourly counts are application-audit counts, not raw HTTP/SSE request counts.

## Legacy retirement (separate approval; no publish required)

After all client migrations are verified, obtain explicit retirement approval.
The Agent must not run these commands merely because this tooling PR is merged.
Run one command at a time in a private, unrecorded Shell:

```sh
.local/cmh-v2-venv/bin/python -B v2/c3_revoke_legacy.py legacy-mcp
# legacy-rest requires its own retirement approval:
.local/cmh-v2-venv/bin/python -B v2/c3_revoke_legacy.py legacy-rest
```

Only those two slugs are accepted. Before any Owner login, the command checks
usage through the same `cmh_app` read-only connection and report as
`c3_legacy_usage.py`. The latest event includes transport activity, even DENYs.
Less than 24 hours since last-seen (or a future timestamp) blocks retirement.
There is no override flag. No retained events means no recorded use.

Type the exact slug to confirm, then enter Owner email/password privately through
the existing `owner_session`. SQL closes before HTTPS begins. The native API lists
credentials, revokes only active `legacy_shared` credentials belonging to that
principal, then re-lists and requires each observed `revoked_at` plus zero active
legacy credentials. Expired, already-revoked, non-legacy and other principals'
credentials are untouched. Owner logout is attempted even on failure.

Output is limited to the principal slug, the first eight characters of each
revoked credential ID, its verified revocation timestamp, and post-action active
counts for that principal (all kinds and legacy-only). No token, hash, full ID,
credential name or response body is printed or saved. An HTTP failure stops the
command without retrying any revocation, even if its outcome is unknown. Inspect
native status before any manual rerun; a failed command can have partial effects.

The usage check is a point-in-time safety check, not a lock against a client
returning during confirmation/login. Keep legacy clients stopped. Do not treat
transport activity alone as completed whoami/read/write verification.
